// holdings enrichment
Yahoo-side enrichment looks up each holding's ticker on Yahoo and fills in facets the row doesn't already carry. Two paths use this list:
  • Yahoo top-10 fetch — the rows are freshly minted, so every ticked field is populated.
  • Enrich through Yahoo button on the fund's holdings tile — only fills BLANK cells, so a manually uploaded holdings list is never overwritten.

Lookups are cached for 90 days per ticker and shared across funds — every fund holding AAPL benefits from a single lookup. Tick the fields you want enriched.
// data freshness
How long each group of fund data may be reused before a reload refetches it. Set per group rather than per cache file, because how quickly data goes stale is a property of the data: a fund's structure barely moves, its costs are restated a few times a year, its price is stale the next morning.
0 means always refetch. Fields you have set to your own value are never refetched whatever this says.

// fund scoring
Funds are ranked on cost, size and trailing returns, and the rankings are blended into one score per fund. Each number below is a relative weight — they do not have to add up to anything, since the blend divides by the weights it actually used. A weight of 0 removes that component entirely.

Component weights blend the three top-level rankings. Return-period weights blend the six trailing windows into the single returns ranking, and only matter when the returns component has a non-zero weight.

A fund missing data for a component is scored on the components it has, with the remaining weights renormalised — so a missing TER does not push a fund to the bottom, but its score is thinner. Fund size is a pass/fail test against the floor below rather than a ranking: past "big enough", more is not better.
A fund at or above this size scores 100 on the size component; below it, 0. In the fund's own currency — no FX is applied, so pick a round number with room for the difference.
// portfolio holdings
On the portfolio's Holdings sub-tab, the same underlying holding held by two or more funds is merged into a single row. This setting picks which field decides that two positions are "the same holding". Ticker is the most reliable; ISIN is exact but often blank on Yahoo top-10 rows; Name matches on a normalised form (case- and spacing-insensitive) but is not fuzzy. A blank value for the chosen field never matches — each such holding stays its own row.
Applies to every portfolio. Changing it re-aggregates the Holdings sub-tab the next time it's opened.

Resolve unmatched values

Every distinct value that matched nothing in the resource files, from holdings, Yahoo, factsheets and uploaded CSVs alike. Pick what a value means and the alias is written to the resource file: every occurrence in every fund resolves on next read, and nothing is rewritten. Sector and country targets name a level — mapping "AI Hype" to the semiconductors sub sector claims the source told us the sub sector, mapping it to technology claims it told us only the sector. Values that are junk — a footnote marker, a stray header — have no honest target; leave them, they sink to the bottom on the weight sort.

Holdings rows, for what an alias cannot express: a blank value, which has nothing to alias, and a row that is simply wrong rather than differently spelled — a fact about that row, not about the vocabulary. Unmatched cells are shown in red. Sort by clicking a column header; filter to narrow the list; tick rows to select; then click edit on a column header to set a canonical value on every selected row. For a spelling the vocabulary has simply never seen, use the By value tab — one alias fixes every fund at once.

No unmatched values. Everything is normalised.

Edit exposure targets

Set target percentages for the buckets you care about. Buckets you don't add are "untargeted" — the portfolio's actual exposure in those buckets is summarised separately. Targets don't have to reach 100%; whatever is left over is just untargeted.

The figure beside each heading is what those targets commit, not the levels added up. Targets nest, so a target set at a finer level counts inside the one that contains it: semiconductors 15% within technology 35% commits 35%, not 50%. Past 100% the figure turns amber, because at that point the category really is over-committed.
